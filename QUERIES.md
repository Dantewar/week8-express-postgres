Week 10 – Sequelize SQL Query Comparison

Skill 5 – Look Under the Hood

Introduction

In this exercise, I used Sequelize logging to inspect the SQL generated by my Library API. I compared the generated queries with SQL JOIN statements that I would have written manually using PostgreSQL.

The purpose was to understand how Sequelize handles database relationships and how ORM methods translate into SQL.

1. Get an Author with Their Books

Endpoint: GET /authors/1/books

Sequelize method: Author.findByPk() with include.

SQL Generated by Sequelize

SELECT
  "Author"."id",
  "Author"."name",
  "books"."id" AS "books.id",
  "books"."title" AS "books.title",
  "books"."genre" AS "books.genre",
  "books"."published_year" AS "books.published_year",
  "books"."author_id" AS "books.author_id"
FROM "authors" AS "Author"
LEFT OUTER JOIN "books" AS "books"
  ON "Author"."id" = "books"."author_id"
WHERE "Author"."id" = 1
ORDER BY "books"."id" ASC;

My Manual SQL Query

SELECT
  authors.id,
  authors.name,
  books.id AS book_id,
  books.title,
  books.genre,
  books.published_year,
  books.author_id
FROM authors
LEFT JOIN books
  ON authors.id = books.author_id
WHERE authors.id = 1
ORDER BY books.id ASC;

Explanation

Both queries retrieve an author and their books.

Sequelize uses a LEFT OUTER JOIN to include the related books. My manual SQL uses LEFT JOIN, which has the same meaning.

The main difference is the column aliases. Sequelize uses aliases such as books.title to organize the results into nested JavaScript objects.

In my manual SQL, I used simpler aliases such as book_id.

2. Get a Member with Their Loans

Endpoint: GET /members/1/loans

Sequelize method: Member.findByPk() with nested include for Loan and Book.

SQL Generated by Sequelize

SELECT
  "Member"."id",
  "Member"."name",
  "Member"."email",
  "loans"."id" AS "loans.id",
  "loans"."member_id" AS "loans.member_id",
  "loans"."book_id" AS "loans.book_id",
  "loans"."borrowed_at" AS "loans.loan_date",
  "loans"."returned_at" AS "loans.returned_at",
  "loans->book"."id" AS "loans.book.id",
  "loans->book"."title" AS "loans.book.title"
FROM "members" AS "Member"
LEFT OUTER JOIN "loans" AS "loans"
  ON "Member"."id" = "loans"."member_id"
LEFT OUTER JOIN "books" AS "loans->book"
  ON "loans"."book_id" = "loans->book"."id"
WHERE "Member"."id" = 1
ORDER BY "loans"."borrowed_at" DESC,
         "loans"."id" DESC;

My Manual SQL Query

SELECT
  members.id AS member_id,
  members.name AS member_name,
  members.email,
  loans.id AS loan_id,
  loans.member_id AS loan_member_id,
  loans.book_id,
  loans.borrowed_at AS loan_date,
  loans.returned_at,
  books.id AS book_record_id,
  books.title AS book_title
FROM members
LEFT JOIN loans
  ON members.id = loans.member_id
LEFT JOIN books
  ON loans.book_id = books.id
WHERE members.id = 1
ORDER BY loans.borrowed_at DESC,
         loans.id DESC;

Explanation

This query connects three tables: members, loans and books.

The loans table acts as a junction table between members and books. It stores information about each borrowing event, including the borrowing date and return date.

Sequelize generates two LEFT OUTER JOIN operations to retrieve the member, their loan records and the related book information.

In my manual query, I used the same JOIN logic with simpler table and column aliases.

3. Does Sequelize Use INNER JOIN or LEFT OUTER JOIN?

In my tests, Sequelize generated LEFT OUTER JOIN statements.

This happens because Sequelize normally uses a LEFT OUTER JOIN for an include association when required is not enabled.

A LEFT OUTER JOIN returns the main record even when there are no matching records in the related table.

For example, an author can still appear even if they have not written any books in the database.

An INNER JOIN would only return records where matching data exists in both tables.

Using required: true in a Sequelize include can change the relationship query to an INNER JOIN.

4. What Is Different Between Sequelize SQL and My SQL?

The main differences are:

Aliases: Sequelize automatically creates aliases such as books.id, loans.loan_date and loans.book.title. My manual queries use simpler aliases.

Quoted identifiers: Sequelize surrounds table and column names with double quotes, while my manually written SQL generally does not need them.

Nested relationships: Sequelize uses aliases such as loans->book to distinguish nested associations.

Object mapping: Sequelize uses the generated column aliases to organize SQL results into JavaScript model instances with nested associated data.

Query readability: My manual SQL is easier for me to read, while Sequelize automatically generates the JOIN structure from the defined model relationships.

Both approaches use SQL to communicate with PostgreSQL.

5. What Did I Learn?

I learned that Sequelize does not replace SQL. It generates SQL based on JavaScript model methods and the associations defined in the application.

Using include makes it easier to retrieve related data without manually writing JOIN statements.

However, understanding SQL is still important because I need to be able to inspect generated queries, identify errors and understand how database relationships work.

This exercise helped me connect my previous knowledge of PostgreSQL JOINs with Sequelize ORM.

Conclusion

Sequelize makes database operations easier to organize in JavaScript, especially when working with CRUD operations and relationships.

By comparing the generated SQL with my manually written queries, I could see that Sequelize uses the same relational database concepts that I learned in earlier backend lessons.
